4.79bFIXED
~~~~~~~~~~~~~
If the processor supports SSE4.2 (which we consider an indicator of a modern CPU, 2008+), the cache test is performed for 16 MB (instead of 8), which gives more adequate results (it does not fit entirely into L3). // For 32 MB: MemSizePriznak = 3 and ResultsNew DB 13 DUP(0) -> 14

The main screen also now displays the maximum SSE version supported by the processor.

Fixed overflow and logic failure when cache speed > 40 GB/s.

Fixed crashes in VMware. The instruction length was calculated incorrectly (tnx Claude). Now the length is calculated by the compiler.

Reduced the constant affecting the display of the 'Average/Max seek time' section in the HDD test. For its proper display on SSDs.

Fixed the display of some data for Core2 processors (which overlapped with PIII in cpuid).

Improved the Memory Bandwidth test on Core2+, by increasing the size of the tested memory to 8-16 MB (otherwise everything goes into the cache). And by disabling GetMemPeakBandwidth128, which produces inflated results there.


Rus

Если процессор поддерживает SSE4.2 (2008+ год. будем считаеть их относительно современными), тест кэша выполняется для объема 16 МБ (а не 8 МБ), что обеспечивает более адекватные результаты (он не попадает целиком в L3). 
// Для 32 МБ: MemSizePriznak = 3; ResultsNew DB 13 DUP(0) -> 14.

Кроме того, на главном экране теперь отображается максимальная версия SSE, поддерживаемая процессором (раз уж мы её определили).

Исправлено переполнение при умножении, при скорости кэша > 40Гб/с. Ломалась логика определяющая кэши.

Исправлены вылеты в vmware. Была неверно подсчитана длина инструкций. Теперь длину считает компилятор.

Уменьшена константа влияющая на показ раздела с 'Average/Max seek time' в тесте HDD. Для его нормального отображения на SSD.

Исправлено отображение некоторых данных процессоров Core2 (которые в cpuid пересекались с PIII).

Улучшен тест Memory Bandwidth на Core2+, увеличением размера тестируемой памяти до 8-16Мб (иначе всё уходит в кэш). И отключением GetMemPeakBandwidth128, которая там даёт завышенные результаты.
